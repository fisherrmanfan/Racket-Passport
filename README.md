# Racket Passport API

Read-only API over the `racket_catalog` view (populated by the
[racket_database_etl](https://github.com/fisherrmanfan/racket-database-etl)
pipeline). Lets a client type in a racket and get back the matching row with
full specs, plus typo-tolerant autocomplete.

## Setup

```bash
npm install
cp .env.example .env   # fill in DATABASE_URL
npm run migrate        # enables pg_trgm + adds the autocomplete index (one-time)
npm start
```

## Endpoints

- `GET /health`
- `GET /autocomplete?q=blade+9&limit=10` — typo-tolerant typeahead over racket names, ranked by trigram word similarity.
- `GET /match?q=biomimetic+tour&limit=5` — word-order-independent name match (every typed word must appear in the name), returns full spec rows, closest (shortest) name first.
- `GET /rackets/:id` — single racket by numeric `racket_id` or `source_id` (pcode).
- `GET /rackets?manufacturer=&name=&hsMin=&hsMax=&wMin=&wMax=&swMin=&swMax=&fMin=&fMax=&limit=&offset=` — filterable browse list.

## Why not a Hidden Markov Model for autocomplete?

Racket names are a fixed, known catalog (~2,700 rows), not a sequence
generated by hidden state transitions — so this is a typo-tolerant
prefix/substring search problem, which `pg_trgm` (trigram similarity, GIN
index) solves natively: no training, no retraining when the catalog updates,
and it out-performs an HMM on accuracy for this kind of lookup.
